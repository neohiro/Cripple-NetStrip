--- layout: default --- {%- comment -%} _layouts/host.html — one page per subdomain in the frenzypenguin.media zone. Uses the extra_css / extra_js hooks in default.html to pull in the directory styling and the swirl controller. It deliberately does NOT fork default.html: every byte of the site chrome stays in one place, so a change to the header or the footer reaches these pages too. FRONT MATTER EXPECTED slug the key in _data/hosts.yml. Required — the layout looks the record up by slug rather than accepting it as a parameter, because a page that can be handed a record it does not match is a page that can render the wrong bio. title page title. Falls back to the record's title. description meta description. Falls back to the record's blurb. OPTIONAL extra_note a paragraph appended under the status block, for the pages that need to say something the data file cannot. A NOTE ON extra_css / extra_js This layout deliberately does NOT declare extra_css / extra_js in its own front matter, because it would not work. Jekyll merges a layout's front matter into the payload, not into `page`, and default.html reads page.extra_css. A page using this layout must therefore declare both keys itself; every generated host page does, and .github/scripts/check_host_pages.py fails the build if one does not. WHY THE RECORD IS THE CONTENT hosts.yml is the single source of truth. Editing this page's front matter changes the title and nothing else; to change what the page says about a host, edit hosts.yml, so the directory, the status report and this page can never disagree. {%- endcomment -%} {%- assign h = site.data.hosts.hosts | where: "slug", page.slug | first -%} {%- assign cats = site.data.hosts.categories -%} {%- assign cat = cats[h.category] -%} {%- comment -%} A slug with no matching record is a build error, not a blank page.
